# Pingo web

Svelte 5 UI backed by RxFerrix 0.6.1 and browser WebRTC. Run these commands from the repository root:

```sh
export PATH="$HOME/.cargo/bin:$PATH"
cargo run -p pingo-server -- serve --dev --http 127.0.0.1:8090 \
  --codegen-out apps/web/src/lib/rxferrix
```

In a second terminal:

```sh
cd apps/web
bun install
bun run dev
```

Open the URL printed by Vite. Its `/api` proxy includes the RxFerrix sync WebSocket; `/rtc` proxies media
signaling. Both target `http://127.0.0.1:8090`, overridable with `PINGO_BACKEND_URL`. Media itself uses the
backend's UDP port, not the HTTP proxy. See `crates/pingo-server/README.md` for `PINGO_PUBLIC_IPS`, UDP firewall
configuration, media admission secrets, and OAuth/email configuration. HTTPS is required outside localhost for
microphone, camera, and screen capture.

## Data and auth

`src/lib/rxferrix` is generated by the running backend and committed. Regenerate it after backend API changes;
do not hand-edit it. `src/lib/data/api.ts` uses those exact references, retaining generated fields and types while
allowing plain route IDs at the UI boundary. Components retain the `useQuery(api.module.fn, () => args)`,
`usePaginatedQuery`, and `useMutation` style from `@rxferrix/svelte`.

Live mode is the default. Password sign-up/sign-in, magic links (with an email-code alternative), second-factor
sign-in, configured OAuth providers, session restoration, and sign-out use RxFerrix auth. Unconfigured OAuth
buttons stay hidden. Invite previews work before sign-in; accepted invites and new spaces navigate to their real
room IDs. Accounts without spaces can create one or paste an invite.

Messages use cursor pagination and optimistic updates. Optimistic IDs/timestamps are created once outside the
update closure so RxFerrix can replay it safely. Threads, reactions, edits, soft deletes, attachments, search,
Catch up, DMs, profile photos, space icons/invites, and room settings use the generated API. Typing is throttled
to once every two seconds; presence sends an initial heartbeat and then one every 60 seconds. Visible rooms are
marked read on opening, live arrivals, and returning to the tab. Server error codes have friendly wording.

For design work without a backend:

```sh
cd apps/web
VITE_PINGO_MOCK=1 bun run dev
# Run the original design/screenshot suite:
VITE_PINGO_MOCK=1 bun run test:e2e
```

The mock adapter, seed, and call simulation remain isolated behind that build-time opt-in. Mock auth and media
are local simulations. The sound-check wizard always uses the browser's actual device APIs, including in mock
mode. Generated files need no backend at build time.

## Calls

`BrowserCallController` obtains a fresh `voice.join` token, sends camelCase messages matching
`crates/pingo-proto/src/signal.rs`, and negotiates non-trickle SDP on `/rtc`. It handles server re-offers,
client-offer collisions, receive-mid/participant mapping, unpublished tracks, and bounded reconnect with fresh
admission. Only SFU hooks update durable voice state; the sidebar observes `rooms.list().voice`.

Opus negotiates FEC/DTX and retains the browser's RFC 6464 audio-level extension. Studio rooms request stereo,
256 kbps Opus, and disable microphone echo cancellation, noise suppression, and automatic gain. Web Audio routes
remote audio through per-user gain/pan and applies the Lounge's pure distance mix. The sound check enumerates
real devices, meters microphone input, records locally for playback, and saves device preferences. Browser
noise suppression uses the browser's boolean processing control; Gentle/Strong do not install a separate DSP.

Mute/deafen use `SetState`. Speaking, reactions, hands, pointers, and strokes use the `pingo` data channel.
Pointers and drawings are scoped to the translated screen mid. Quality uses recent loss, jitter, and RTT from
`getStats`. Screen capture supports optional system audio, Text (detail, up to 4K, 10–15 fps) and Motion
(1080p60) constraints. Screen and camera senders request two simulcast layers, with a single-layer fallback.
Remote video sends its visible tile height (or zero when hidden) to `SetVideoQuality`.

Screen/camera capture and resolution depend on browser support and the selected source. Reconnect restores the
microphone and mute/deafen state; screen/camera capture must be explicitly restarted. A Resume audio control
handles browser autoplay restrictions. TURN/ICE-TCP remain SFU deployment gaps; UDP connectivity is required.
Chromium is covered automatically. Safari/Firefox, real-device acoustics, and WAN/NAT/TURN interoperability have
not been verified here. Spatial positions currently come from the local Lounge layout; moving your avatar
changes your listening mix but does not broadcast position to other clients (the signaling contract has no
position event). Pop-out and desktop notifications remain existing UI placeholders/preferences.

## One-origin serving

Build from `apps/web`, then serve from the repository root:

```sh
(cd apps/web && bun run build)
PINGO_WEB_DIR=apps/web/dist PINGO_APP_URL=http://127.0.0.1:8090 \
  PINGO_PUBLIC_IPS=127.0.0.1 \
  cargo run -p pingo-server -- serve --dev --http 127.0.0.1:8090
```

Open `http://127.0.0.1:8090`. The backend serves the SPA, deep-link refreshes, assets, uploads, API, sync socket,
and `/rtc` signaling from this origin; Vite is unnecessary. `PINGO_APP_URL` must match the public app origin for
auth redirects. For production, omit `--dev`, configure real mail/OAuth and the database `PINGO_MEDIA_SECRET`,
and expose HTTPS/WSS plus UDP as described in the backend README. Static serving is already implemented by the
backend; no server API or signaling contract change was needed for it.

## Verification

```sh
cd apps/web
bun run check
bun run test
bun run build
# Build once before the E2E runner starts the binary:
(cd ../.. && cargo build -p pingo-server)
bun run test:e2e
# Run the same real-server suites against backend-served dist, with no Vite:
PINGO_E2E_PRODUCTION=1 PINGO_E2E_PORT=8090 bun run test:e2e
```

E2E starts a development backend in a fresh temporary `--dir`, with an ephemeral UDP port, then cleans up its
processes/data. The default HTTP port is 8098 and Vite port is 5188; override `PINGO_E2E_PORT`,
`PINGO_E2E_WEB_PORT`, or `PINGO_SERVER` (absolute binary path) when needed. Ports must be free. The runner
advertises a concrete local IPv4 interface for Chromium media; there are no external services. Chromium uses
fake microphones/cameras. The call suite substitutes only `getDisplayMedia` with an animated canvas stream to
avoid a headless capture dialog; production capture, negotiation, SFU forwarding, and decoding stay real.

The suites exercise two-context auth/invites, live messages, reactions/threads, unread/read state, mentions,
DMs/inbox completion, history pagination, uploads/search/edit/delete, profile/room settings, and email codes.
Calls assert remote audio bytes in both directions, speaking and mute, real camera/screen decode, sidebar voice
state, reactions/hands/pointers/strokes, and reconnect. Vitest covers SDP, Studio constraints, stats labels,
retry policy, message parsing/grouping, pagination, and spatial mixing. Real-data screenshots are refreshed at
`screenshots/real-*.png`; the other screenshots retain the design/demo journeys.

The separately committed SFU socket fix reads Linux IP_PKTINFO/IPV6_PKTINFO for wildcard binds, maps to the
advertised ICE candidate, and includes wildcard/media regressions. Existing explicit loopback binds still work;
non-Linux multi-interface wildcard binds need platform packet-info support. `crates/pingo-server` and both
public contracts are unchanged. The only shared-file change is the Cargo.lock entry for the SFU socket dependency.

Verified on 2026-10-23: `bun run check` reports zero errors/warnings; all 24 Vitest tests pass; `bun run build`
succeeds. All four real-server Playwright suites pass through Vite and through backend-served `dist` at
`127.0.0.1:8090`; all ten mock/design suites pass. `cargo test -p pingo-server` passes 20 tests,
`cargo test -p pingo-sfu` passes 18 tests, and SFU formatting/clippy checks pass with warnings denied.
